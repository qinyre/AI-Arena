## 🔍 技术决策说明

### 为什么使用 Tailwind 而非 CSS-in-JS？

✅ **优势**:
- 构建时生成，零运行时开销
- 原子化类名，可复用性高
- 响应式设计简洁（sm:, md:, lg:）
- 渐变和阴影支持完善

❌ **劣势**:
- 类名字符串较长（已通过组件封装缓解）

### 为什么不使用动画库（Framer Motion）？

✅ **CSS 原生动画足够**:
- 简单的缩放、旋转、透明度变化
- GPU 加速性能好
- 零依赖，包体积小

📦 **未来可选**:
- 复杂的序列动画可引入 Framer Motion
- 物理动画可引入 React Spring

### 为什么使用 Set 管理展开状态？

```javascript
// Set: O(1) 查找和修改
const [expandedEvents, setExpandedEvents] = useState<Set<number>>(new Set())

// 对比 Array: O(n) 查找
const [expandedEvents, setExpandedEvents] = useState<number[]>([])
```

**优势**: 事件数量可能达到 100+，Set 的性能优势明显。

```javascript
const getEventConfig = (type: string) => {
  const configs: Record<string, EventConfig> = {
    event_type: {
      icon: '🎮',
      iconBg: 'bg-gradient-to-br from-green-500 to-emerald-600',
      borderColor: 'border-green-500/30',
      bgGradient: 'bg-gradient-to-br from-green-950/40 to-emerald-950/20',
      glowColor: 'shadow-green-500/10',

  return configs[type] || defaultConfig
```

## 💡 设计启示

### 关键学习

1. **视觉层次 > 装饰元素**
   - 不是添加更多，而是让现有元素层次分明

2. **隐喻的力量**
   - AI 推理 = 查看代码，用户立即理解

3. **微妙胜于浮夸**
   - 30% 透明度 > 100% 不透明
   - 1% 放大 > 10% 放大

4. **动画是交互反馈**
   - 每个动画都传递信息，不是纯装饰

5. **一致性建立信任**
   - 统一的配色逻辑
   - 统一的动画时长
   - 统一的间距系统
