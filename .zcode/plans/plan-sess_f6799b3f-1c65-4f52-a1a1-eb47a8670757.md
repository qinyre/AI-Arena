## 方案一最终计划:6 家 Provider 接入(5 兼容 + Claude)

### 核心架构
确认全部 6 家 provider 的协议:
| Provider | 协议 | base_url | 用哪个 client |
|---|---|---|---|
| OpenAI | openai 兼容 | `api.openai.com/v1` | OpenAICompatibleClient |
| DeepSeek | openai 兼容 | `api.deepseek.com/v1` | OpenAICompatibleClient |
| SiliconFlow | openai 兼容 | `api.siliconflow.cn/v1` | OpenAICompatibleClient |
| Gemini | openai 兼容 | `generativelanguage.googleapis.com/v1beta/openai/` | OpenAICompatibleClient |
| Qwen(DashScope) | openai 兼容 | `dashscope.aliyuncs.com/compatible-mode/v1` | OpenAICompatibleClient |
| Ollama(本地) | openai 兼容 | `localhost:11434/v1` | OpenAICompatibleClient |
| Anthropic | 专属协议 | `api.anthropic.com` | ClaudeClient |

**结论:6 家里 5 家共用一个 client,只有 Claude 单独。无需引入任何新 SDK 依赖**——现有 `openai` + `anthropic` 两个包就够,Gemini/Qwen/DeepSeek/SiliconFlow 全部通过 OpenAI SDK 改 base_url 接入。

### 实施步骤(分两个阶段)

---

#### 阶段 0:环境准备(计划批准后第一步)

1. **创建虚拟环境**(backend 下):
   ```bash
   cd backend
   python -m venv .venv
   source .venv/Scripts/activate   # Git Bash on Windows
   ```
2. **更新 `requirements.txt`**,加 pytest(测试用)、保留 openai/anthropic:
   ```
   openai>=1.3.0
   anthropic>=0.18.1
   ... 现有其余保持 ...
   pytest>=8.0.0
   pyyaml==6.0.1
   ```
3. **安装依赖**:`pip install -r requirements.txt`
4. 把 `.venv/` 加进 `.gitignore`(避免提交虚拟环境)。

---

#### 阶段 1:代码改造(8 个文件)

**1. 重写 `backend/config/models.yaml`** — 单一数据源,6 家 provider
每家含 `protocol`(openai/anthropic)、`api_base`、`api_key_env`、`models`(含 cost_in/cost_out 每 1M token、context)。default 设为 `deepseek/deepseek-chat`(国内直连、便宜、适合开发)。成本单位统一为 per 1M。

**2. 新建 `backend/app/llm/registry.py`** — Provider 注册表
- `load_registry()` 读 yaml,返回 `{provider: ProviderConfig}`。
- `ProviderConfig` / `ModelInfo` dataclass。
- `get_model_info(provider, model)` 供成本计算。
- 模块级单例,懒加载,启动读一次。这让 yaml 从死文件变活数据源。

**3. 改 `backend/app/llm/openai_client.py`** — 泛化
- `OpenAIClient` → `OpenAICompatibleClient`(更准确)。
- `cost_per_1k_*` → `cost_per_1m_*`,公式 `/1000`→`/1_000_000`。
- 默认 model → `gpt-4.1-mini`。
- `OllamaClient` 保留,继承 `OpenAICompatibleClient`。
- 保留 `OpenAIClient = OpenAICompatibleClient` 别名,向后兼容现有 import。
- JSON 解析失败的正则降级逻辑保留(兼容各家的 JSON mode 差异)。

**4. 改 `backend/app/llm/claude_client.py`** — 更新模型 + 成本单位
- 默认 model → `claude-sonnet-4-5`。
- `cost_per_1k_*` → `cost_per_1m_*`,公式同步。

**5. 微调 `backend/app/llm/client.py`** — docstring 说明成本单位 per 1M,接口签名不变。

**6. 重写 `backend/app/core/orchestrator.py` 的 `initialize()`** — 用 registry 消除 if/elif
当前 3 个硬编码 provider 分支 → 改为"查 registry → 按 protocol 造 client"。新增 provider 只改 yaml 不改代码。这是方案一的核心价值。

**7. 更新 `backend/.env.example`** — 补全 6 家 key
```
OPENAI_API_KEY / ANTHROPIC_API_KEY / DEEPSEEK_API_KEY /
SILICONFLOW_API_KEY / GEMINI_API_KEY / DASHSCOPE_API_KEY
```

**8. 新建 `backend/tests/test_registry.py`** — 不依赖真实 API
- registry 加载、6 家 provider 都能查到模型。
- cost 计算用 per_1m 正确。
- orchestrator client 工厂逻辑(mock,不联网)。
- 更新现有 test_game.py / test_claude.py 的模型 ID。

---

### 不在本次范围
- ❌ 推理模型适配(reasoning_effort)——独立议题
- ❌ agent.py / game.py 游戏逻辑不动
- ❌ WebSocket / 前端不动
- ❌ 不引入新 SDK(Gemini/Qwen 走 OpenAI SDK,无需 google-genai/dashscope 包)

### 验证(不花 API 钱)
registry/cost/工厂逻辑全用单元测试覆盖,不真实联网。端到端验证由用户配自己的 DeepSeek key 手动跑。

### 风险与回退
- 模型 ID/定价来自搜索(2026-07),yaml 注释标"参考价以官方为准",且可配。
- Gemini base_url 结尾斜杠是硬性要求(`/v1beta/openai/`),会在 registry 注释强调。
- 在新分支 `feature/multi-provider` 做,不动 main。保留 `OpenAIClient` 别名向后兼容。
